# Publishing handoff

## Purpose

Ensure the approved master, captions, metadata, and destination match before external publication.

## Input contract

Approved render, caption policy, destination, title and description, rights status, and explicit publishing approval.

## Steps

1. Identify the exact master and hash it; inspect that file rather than a preview or similarly named export.
2. Choose one caption treatment per platform: burned-in captions or a platform caption track, unless deliberate duplication is approved.
3. Preview the destination-specific package, including ratio, audio, caption placement, title, and thumbnail.
4. Record approval for the exact package; publish through an external tool only when authorized, then inspect the live result.

## Acceptance evidence

Approved master hash, caption decision, package checklist, approval record, and live URL or external publication receipt.

## Fail and repair rules

A clean render is not automatically the correct master. Duplicate captions, mismatched hashes, or missing approval block publication and require a new preview.

## Synthetic example

A synthetic upload uses a clean master although the approved version contains required disclosures. The handoff fails; select and recheck the approved master before upload.

## Limitations

The kit never uploads or publishes. Its approval field is an operator assertion and does not grant platform access or establish authority.
